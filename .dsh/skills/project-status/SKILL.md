# Project Status

Собирает статус из двух источников: `IN_PROGRESS.md` (основное) и `TODO.md` (бэклог). Задача отчёта — чтобы человек за 10 секунд понял, где что происходит.

## Обязательный формат

Отчёт **всегда** отдаётся по шаблону из раздела «Эталон»: та же последовательность блоков, та же разметка, те же эмодзи и разделители. Меняй наполнение (задачи, числа, фокус), но не структуру. Другой формат — только по прямой просьбе пользователя.

## Шаги

1. Прочитай корневой `TODO.md`: секции `## Бэклог` (четыре проекта) и `## Прочее`.
2. Найди журналы: `glob` по `**/IN_PROGRESS.md` (кроме `saspik-private`).
3. Собери по каждому проекту: счётчик `> Незавершённых задач: N`, первую задачу с тегом ≠ `[Выполнено]`, её строку `Статус:` и 2–4 содержательных пункта; список задач бэклога.
4. Отдай отчёт по эталону ниже. Служебные детали (перечни файлов, команды) не выводи — только смысл работ.

## Визуальная иерархия

| Уровень | Разметка | Что это |
| :--- | :--- | :--- |
| 1. Заголовок отчёта | `#` | одна строка «Статус проектов · САСПИК» |
| 2. Проект | `##` | эмодзи + имя проекта |
| 3. Блок внутри | `>` + `**жирный**` | счётчик в callout, задача — жирным |

- `##` даёт крупный размер и линию под заголовком, но проекты дополнительно отделяются горизонтальной линией `---` (пустая строка до и после): так границы читаются в любой теме и на узком экране.
- Сводка сверху — таблица: её видно первым экраном.
- Счётчик — `>` (blockquote): визуально выделяется, не сливается с текстом.
- Задача — единственная жирная строка в блоке; тег вынесен в эмодзи-бейдж.

## Цветовые бейджи статусов

Эмодзи — единственный надёжный «цвет» в markdown-чате (CSS и inline-стили рендерер может вырезать). Подставляй бейдж по тегу:

| Тег в журнале | Бейдж |
| :--- | :--- |
| `[В работе]` | 🔵 **В работе** |
| `[На доработку]` | 🟠 **На доработку** |
| `[Нужно взять в работу]` | 🟡 **Нужно взять в работу** |
| `[Выполнено]` | ✅ **Выполнено** |
| нет незавершённых | ⚪ **Задач нет** |

## Правила

- Порядок проектов — как в `TODO.md`: meshrover → iot → cluster → greenhouse.
- После сводной таблицы и после каждого блока проекта (включая последний, greenhouse) — пустая строка, `---`, пустая строка. Внутри блока проекта линий нет.
- Между `##`-заголовком и счётчиком — пустая строка; между счётчиком и задачей — пустая строка.
- В блоке — **только одна** незавершённая задача (самая верхняя); остальные покрывает счётчик.
- `[Выполнено]` не выводится.
- Фокус в таблице — 2–5 слов, по теме верхней задачи; нет задачи — `—`.
- Счётчик расходится с фактическим числом — добавь строку `⚠ счётчик расходится: в файле N, фактически M` сразу под callout.
- Нет журнала — `*нет записей*` вместо блока задачи.
- Нет незавершённых — `> **Незавершённых: 0**` и `*нет незавершённых задач*`.
- После четырёх проектов — `## 📦 Прочее` и задачи из `## Прочее` списком курсивом; пусто — `*нет задач*`.
- Заголовок отчёта — один на весь ответ; не дублируй его в тексте.
- Даты в журналы не пишутся; в отчёте дата допустима как «на момент показа» (формат `ДД.ММ.ГГГГ`).
- HTML-разметку и inline-стили не используй: рендерер чата может их вырезать.

## Чек-лист перед отдачей

1. Первая строка ответа — `# 📊 Статус проектов · САСПИК`, без вступлений и подводок.
2. Есть строка `дата · источники`.
3. Таблица: 4 строки, колонки «Проект / Незавершённых / Фокус».
4. После таблицы и между всеми блоками — `---`.
5. В каждом блоке: один `##`, один callout-счётчик, одна жирная задача с бейджем, 2–4 пункта, `**Бэклог · N**`.
6. В конце — `## 📦 Прочее`.
7. После отчёта нет пояснений и комментариев (если пользователь их не просил).
