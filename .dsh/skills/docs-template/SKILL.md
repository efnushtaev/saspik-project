# Шаблон документации ⧫

Единый формат страниц с заголовком `⧫` в репозитории SASPIK.

## Заголовочный блок (обязателен)

```markdown
[↑ <Прародитель>](<относительная ссылка>)

# ⧫ <Название>

#### <описание одной строкой>
<вводные факты — по одному предложению/факту на строку>
```

- **Хлебная крошка** — ссылка на README родителя по глубине: `[↑ Назад](../README.md)` для README подпроекта, `[↑ Saspik-cluster](../../README.md)` для app-README, `[↑ Saspik-cluster](../README.md)` для `docs/*.md`.
- **`# ⧫ <Название>`** — первый заголовок первого уровня.
- **`#### <описание>`** — одна строка сразу после `# ⧫`.
- **Вводные факты** — по одному факту на строку, без многоабзацного интро.

## Секции

Дальше идут `###`-секции по смыслу документа; их состав диктуется содержанием, фиксируется только форматирование.

## Правила форматирования

- Заголовки: `###` — основные секции, `####` — подзаголовок после `# ⧫` и внутренние подразделы, `#####` — подтаблицы и термины.
- Таблицы: выравнивание `| :--- | :--- |`, первая колонка — имя поля, вторая — описание; имена полей в бэктиках: `` `field` ``.
- Ключевые термины — жирным `** **`.
- Тире — длинное с пробелами: ` — `.
- Код — fenced-блоки с языковым тегом (` ```json `, ` ```cpp `, ` ```flux `).
- Кросс-ссылки между документами — относительные: `[docs/logs](logs.md)`, и «см. <Название>» в тексте.
- Таблица «История изменений» в конец документа не добавляется.

## Чек-лист нового документа

1. Проверь, подхватит ли генератор `docs.html`: README проекта, README сервиса/приложения или `.md` в `docs/`; файлы с префиксом `wip_` не краулятся.
2. Вставь заголовочный блок по шаблону.
3. Наполни `###`-секции по правилам выше.
4. Сверься с ближайшим по типу существующим документом (README проекта / README сервиса / doc в `docs/`).
5. Для генерации страницы используй скилл `docs-gen`.
