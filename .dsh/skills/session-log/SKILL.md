# Session Log

Журнал сессий лежит в `opencode/session_log.md` (в рабочей копии — symlink на `saspik-private/opencode/session_log.md`). Это приватная часть вне публичного git: правки туда не попадают в коммиты основного репозитория.

## Автоматический запуск

Пиши лог без явной просьбы, когда:

- **конец сессии** — пользователь прощается, завершает работу или просит подвести итоги;
- **сжатие контекста** — в истории появилось резюме/компакция; сразу после этого запиши блок по прошедшей части;
- **крупная веха** — коммит+push, успешная сборка, выпуск документации, законченный этап.

## Формат записи

1. Прочитай `opencode/session_log.md` (`read`). Файла нет — начни с пустого.
2. Проверь, начинается ли последняя запись с **сегодняшней даты** (формат `**ГГГГ-ММ-ДД**`).
   - **Да** — допиши описание с новой строки, дату не повторяй.
   - **Нет или файл пуст** — добавь в конец блока:

     ```


     **ГГГГ-ММ-ДД**
     Краткое описание выполненных задач (1–3 предложения).
     ```

     Две пустые строки — отступ от предыдущего блока, затем жирная дата, затем описание.
3. Пиши по существу: что сделано, где (файлы/коммиты), что осталось и что проверено вручную. Без воды и без пересказа диалога.
4. Если в контексте есть готовый блок `SESSION_LOG:` — перенеси его под текущую дату, не дублируя дату при нескольких записях в день.

## Ограничения

- Не создавай отдельный файл на сессию — только дописывание в конец `session_log.md`.
- Не редактируй прошлые записи и не меняй их даты.
- Не коммить этот файл в основной репозиторий: он живёт в `saspik-private`.
