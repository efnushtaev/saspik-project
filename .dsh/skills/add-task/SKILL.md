# Add Task

Добавляет задачу в корневой [`TODO.md`](../../../TODO.md) — единый бэклог монорепозитория (в рабочей копии это symlink в `saspik-private`, фон не важен: работать по пути из корня).

## Когда применять

- «добавь таску», «добавь в TODO», «добавь в бэклог»;
- «добавь таску в saspik-cluster: <текст>»;
- «добавь текущую таску» — про то, что обсуждаем сейчас.

## Бизнес-взгляд

Бэклог читает владелец, а не компилятор: задача должна отвечать, **что он получит и чем рискует без неё**. Поэтому формулировка строится от результата, а не от технологии.

Шаблон записи:

```markdown
- [ ] <Бизнес-результат одной строкой> — <что для этого делаем>

  Зачем: <потеря, риск или стоимость обхода, если не делать>.
  Готово, когда: <наблюдаемый критерий: что видно в UI/логах/на стенде>.
```

Правила:

- **Первая строка** — результат для владельца: «Гарантия исполнения команд», «Данные датчиков не залипают в UI», а не «Проверить `subscribe()`».
- **Зачем** — одна строка про потерю или риск (деньги, урожай, простой, выезд на объект). Не пересказ первой строки.
- **Готово, когда** — проверяемое условие, а не «сделать хорошо»: должно быть видно в UI, логах или на стенде.
- Формулировки без жаргона, который не нужен для понимания; имена файлов и функций — только если без них критерий непонятен.
- Житейские задачи (переименовать ручку, выжечь плату) — можно одной строкой без подстрок: если «зачем» очевидно, не сочиняй его.
- Не выдумывай ценность: если непонятно, что владелец выигрывает, — спроси одним вопросом, а не пиши общие слова.
- Между многстрочными задачами — пустая строка; внутри задачи — без дат и оценок сроков.

## Шаги

1. Прочитай `TODO.md` инструментом `read` и уточни структуру: `## Бэклог` с подсекциями проектов и `## Прочее`.
2. Разбери запрос:

   | Запрос | Чего не хватает | Действие |
   | :--- | :--- | :--- |
   | «добавь таску» | проект и текст | спроси оба |
   | «добавь таску в <проект>» | текст | спроси текст |
   | «добавь таску в <проект>: <текст>» | — | добавляй |
   | «добавь текущую таску» | проект | спроси проект (секции `## Текущая задача` в файле больше нет) |

3. Сформулируй запись по шаблону из «Бизнес-взгляда»: результат → зачем → критерий готовности.
4. Определи целевую секцию — `###` под `## Бэклог`:

   - `### 🤖 saspik-meshrover`
   - `### 📡 saspik-iot`
   - `### 🗄️ saspik-cluster`
   - `### 🌱 saspik-greenhouse`

5. Формат строки — `- [ ] …` без префикса проекта. Существующий текст задач не переписывай: только добавляй новую запись.
6. Вставь запись в конец списка целевой секции через `edit`, сохранив пустые строки и оформление файла.
7. Если назван проект, которого нет среди четырёх, — создай новую `### <Имя>` в конце `## Бэклог` (без эмодзи) и добавь задачу туда.

## Что не трогать

- Задачи с `- [x]` (выполненные).
- Секцию `## Прочее`.
- `IN_PROGRESS.md` — для него есть скилл `in-progress`.

## Критерий готовности

В `TODO.md` появилась ровно одна новая запись в правильной секции: первая строка — бизнес-результат, при необходимости подстроки «Зачем» и «Готово, когда»; остальной файл не изменился.
