САСПИК — Сеть Автоматизированных Систем для Производства и Контроля.
Программно-аппаратное решение для экономики совместного производства.

Структура системы

Аппаратная часть

  • Статичная — теплицы, магистрали, конструкции
  • Крупноузловая — насосы, приводы, пневматика, двигатели
  • Силовая — питание, генераторы, преобразователи
  • Мониторинг — IoT-датчики (температура, влажность, уровень воды)
  • Автоматика — реле, контроллеры, шлюзы
  • Роботы — мехатронные платформы с ROS2

Программная часть

  • Кластер — микросервисное ядро (Node.js, Express, Inversify, PostgreSQL)
  • MQTT брокер — собственный брокер с движком сценариев (RulesEngine)
  • UI — адаптивное SPA для управления юнитами и объектами
  • IoT-прошивки — ESP32 (ESP-NOW, MQTT, deep sleep)
  • CV модуль — компьютерное зрение (планируется)
  • Роботы — ROS2-ноды (планируется)

MeshRover — Distributed swarm for autonomous precision weeding

↑ SASPIK Project

Цель

Создать рой из лёгких автономных ботов, способных без GPS и постоянного интернета совместно обрабатывать поле, передавая на базовую станцию только метаданные детекций.

Ключевые технологии

ESP32-S3, UWB (DWM3000), LoRa mesh, TensorFlow Lite Micro, Raspberry Pi, распределённая локализация.

Текущий статус

Pre-MVP. Начат этап 1: UWB-дальномер на двух ESP32.

План работ

Этап 1: UWB-дальномер (текущий)

  • Настроить PlatformIO проект для ESP32-S3 + DWM3000
  • Инициализировать DWM3000 на двух платах
  • Реализовать TWR (Two-Way Ranging) на одной паре
  • Вывести дальность в UART / Serial Plotter
  • Измерить точность на дистанциях 1–50 м

Этап 2: Локальная навигация

  • Подключить IMU (MPU6050/ICM-20948)
  • Реализовать счисление пути (dead reckoning)
  • Связать UWB + IMU + энкодеры в EKF
  • Получить стабильные координаты относительно опорной точки

Этап 3: LoRa-сеть

  • Настроить LoRa-модуль (SX1276/SX1262)
  • Реализовать простой flooding mesh
  • Пакет: координаты + статус (50–150 байт)
  • Тест: 3+ узла в mesh

Этап 4: Базовое зрение

  • Подключить камеру OV2640 к ESP32-S3
  • Собрать датасет (культура/сорняк)
  • Обучить TFLite-модель (2 класса)
  • Запустить инференс на ESP32-S3

Этап 5: Оркестрация

  • Базовый веб-интерфейс на RPi
  • Приём LoRa-пакетов на RPi
  • Построение карты покрытия
  • Алгоритм виртуальных сил для перераспределения секторов

Бэклог

  • CLI для отладки UWB
  • Симулятор роя (для тестов без железа)
  • Документация по протоколу пакетов

Аппаратное обеспечение

Схемотехника и платы в hardware/.

Программное обеспечение

Прошивки ESP32-S3 в software/.

Утверждённая архитектура (конспект)

Каждый бот (ESP32-S3)

  • Собирает UWB-дальности до соседей, опрашивает IMU и энкодеры.
  • Ведёт счисление пути и вычисляет свои координаты (EKF) относительно опорных точек роя.
  • Имеет камеру OV2640 и выполняет на борту инференс простой TFLite-модели (2 класса: культура/сорняк).
  • Каждое обнаружение упаковывает в короткий пакет (свои координаты, координаты цели, класс, уверенность) и отправляет в общий LoRa-mesh.
  • Получает от базы или соседей задания на коррекцию маршрута, но может работать автономно при обрыве связи.
  • Реагирует на соседей: избегает столкновений, перераспределяет сектора покрытия по алгоритму виртуальных сил.

Базовая станция (Raspberry Pi + LoRa-модуль)

  • Участвует в mesh как привилегированный узел.
  • Аккумулирует все пакеты с детекциями.
  • Строит единую оперативную карту прополки/посева.
  • Выявляет пропущенные участки, оптимизирует глобальное покрытие.
  • Отправляет ботам рекомендательные команды («проверить зону», «сместить фокус»).
  • Предоставляет веб-интерфейс оператору с картой, статусом, зарядом.

Локальная версия для первых тестов (Docker)

На этапах 1–3 базовая станция запускается локально в Docker на машине разработчика:

  • Принимает UART-логи с ESP32 через проброшенный USB (последовательный порт).
  • Логирует и отображает дальномерные данные, позже — координаты и LoRa-пакеты.
  • Веб-интерфейс (FastAPI + легковесный фронтенд) для визуализации в реальном времени.
  • Контейнерная сборка: одна команда docker compose up для поднятия всего стека.
  • Переход на RPi произойдёт на этапе полевых испытаний (Stage 4–5).

Сеть

  • UWB — для точной относительной навигации (без GPS).
  • LoRa (433/868 МГц, mesh) — для обмена координатами, статусом, метаданными детекций и командами.
  • Данные, передаваемые по LoRa, компактны (50–150 байт), что укладывается в возможности технологии.
  • Никакой сырой видеопоток по LoRa не идёт.

Дополнительно (опция, не для MVP)

Позже можно добавить Raspberry Pi на отдельных ботов-лидеров, если понадобится более сложное зрение прямо в поле. Но текущий стек позволяет начать без него.

Что у вас есть сейчас для немедленного старта

  • Чёткая архитектура с разделением обязанностей.
  • Понимание, что и на чём работает: ESP32-S3 для real-time + простого зрения, RPi для оркестрации.
  • Определённый стек протоколов: UWB (TWR), LoRa-mesh (flooding или gossip), бинарные пакеты.
  • План первого шага: оживить UWB-дальномер на двух ESP32.
