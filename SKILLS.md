# SKILLS.md — скиллы агента для САСПИК

Индекс проектных скиллов. Полные инструкции лежат в бандлах `.dsh/skills/<name>/SKILL.md` — это единственный источник истины; здесь только карта «когда что вызывать».

## Как это работает

- DSH автоматически сканирует `<корень>/.dsh/skills/`; каталог скиллов обновляется без перезапуска.
- Формат бандла: `.dsh/skills/<name>/SKILL.md` с frontmatter (`name`, `description`, `whenToUse`) и телом-инструкцией.
- Агент загружает тело по требованию; человеку достаточно открыть файл.
- Скиллы лежат в репозитории и версионируются вместе с кодом. Приватные исходники (`saspik-private/opencode/skills/`) остаются отдельной копией — если правила изменятся, правьте `.dsh/skills/`, а не приватную копию.

## Бандлы с ресурсами

- `docs-gen` — `scripts/generate-docs.js` (Node, требует `marked@4`; запуск без засорения репозитория описан в SKILL.md).

## Общие правила для всех скиллов

- Скилл не отменяет [`AGENTS.md`](AGENTS.md): контракты, инварианты и «чего не делать» действуют всегда.
- Перед правкой файла — прочитать его; перед коммитом — показать дифф и спросить, если не было явного указания коммитить.
- Даты в `TODO.md`/`IN_PROGRESS.md` не пишутся; в `session_log.md` — пишутся, один блок на день.
- Всё, что в `saspik-private/`, вне публичного git: изменения там не попадают в коммиты этого репозитория.

## Обновление

1. Правьте `SKILL.md` напрямую — DSH перечитывает каталог и тело при каждом обращении.
2. Держите `description` одной строкой без `: ` (двоеточие с пробелом ломает YAML-скаляр — используйте `>-` или формулировку без двоеточия).
3. Новый скилл = новая папка `.dsh/skills/<kebab-name>/SKILL.md`; имя в frontmatter должно совпадать с папкой.
