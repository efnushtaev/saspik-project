# ⧫ docs/UnitsService

Юниты хранятся в MongoDB (коллекция `units`) и наполняются сервисом seed при старте (`SeedService`).

Файловый конфиг `units.json` больше не используется — данные живут в БД.

### Формат юнита
Юнит — логическая единица кластера. В БД хранится только базовое описание:
```
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "name": "Теплица-1",
  "description": "Управление климатом в теплице-1"
}
```
Объекты и правила юнита хранятся в **отдельных коллекциях** (`objects`, `rules`) и связаны с юнитом полем `unitId`. При чтении юнита `UnitsService` выполняет джойн: собирает объекты (`objects.unitId === unit.id`) и правила (`rules.unitId === unit.id`) и формирует `UnitDto`.

##### Структура
|Поле|Описание|
|:---------------------|:---------------------------------------------------------------------------|
|`name`|Название юнита|
|`id`|Уникальный идентификатор юнита|
|`description`|Описание юнита|
|`objects`|Массив объектов юнита (джойн из коллекции `objects` по `unitId`)|
|`rules`|Массив правил юнита (джойн из коллекции `rules` по `unitId`)|

##### Составляющие
**object** — сенсор или устройство (см. ObjectsService):
|Поле|Описание|
|:----------------|:----------------------------------------------------------------|
|`id`|Уникальный ID объекта|
|`name`|Название объекта|
|`type`|Тип: `sensor` или `device`|
|`spec`|Массив характеристик: `{ key, model, unit?, minorPart? }`|
|`topic`|MQTT-топик, из которого берутся значения каналов|

**rule** — правило автоматизации (см. RulesService, формат `RuleDto`):
|Поле|Описание|
|:-------------------|:--------------------------------------------------------|
|`id`|Уникальный ID сценария|
|`name`|Название сценария|
|`unitId`|ID юнита, к которому относится|
|`trigger`|Триггер (топик подписки, QoS)|
|`when`|Условие срабатывания|
|`then`|Массив действий|
|`enabled`|Включено/выключено|

### Жизненный цикл
При старте сервера `SeedService` идемпотентно наполняет коллекции `units`, `objects`, `rules` из шаблонов (с подстановкой `${ENV_VAR}` и `${expr:...}`). Удаление юнита через API каскадно удаляет его объекты из коллекции `objects`.

### DTO
Юнит (Unit) — JSON Schema, используемая для передачи данных между сервисами:
```
{
  "$schema": "...",
  "title": "Unit",
  "type": "object",
  "properties": {
    "id": { "type": "string", "format": "uuid", "description": "Уникальный идентификатор юнита" },
    "name": { "type": "string", "description": "Название юнита" },
    "description": { "type": "string", "description": "Описание юнита" },
    "objects": {
      "type": "array",
      "description": "Список объектов (сенсоры/устройства), джойн по unitId",
      "items": { "$ref": "objects-schema.json" }
    },
    "rules": {
      "type": "array",
      "description": "Список правил автоматизации, джойн по unitId",
      "items": { "$ref": "rules-schema.json" }
    }
  },
  "required": ["id", "name", "description"]
}
```
При создании/обновлении юнита принимаются только поля `id`, `name`, `description` (`CreateUnitDto`/`UpdateUnitDto`) — объекты и правила управляются через свои сервисы с указанием `unitId`.
